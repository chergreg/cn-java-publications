# Publications

Application Java de gestion de publications multi-réseaux sociaux, avec une interface JavaFX et une architecture orientée **MVC + Actions UI**.

## Objectif

Le projet permet de gérer différents types de publications pour plusieurs réseaux sociaux, en particulier :

- **LinkedIn**
- **YouTube**

L’application vise à fournir :
- une structure métier claire
- une séparation propre entre données, UI et logique de contrôle
- une base évolutive pour plusieurs vues : **Month**, **Week**, **Day**, **List**

---

# Architecture générale

Le projet repose sur deux axes principaux :

- une architecture **métier orientée objets**
- une architecture **UI en MVC**, complétée par une interface d’actions : `PublicationActions`

## Principes

### 1. Hiérarchie métier
Les publications sont modélisées par une hiérarchie de classes `BO` dérivées d’un tronc commun `PublicationBO`.

### 2. UI en MVC
Chaque écran UI suit une organisation :

- **Model** : état de la vue
- **View** : interface graphique JavaFX
- **Controller** : coordination entre vue, modèle et repository

### 3. Actions UI déléguées
Les actions utilisateur transversales ne sont pas implémentées directement dans les contrôleurs de vue.

Elles sont regroupées dans l’interface :

- `PublicationActions`

Le contrôleur reçoit une implémentation de cette interface par **délégation**.

Cela permet :
- une implémentation **Demo** pour tests rapides
- une implémentation **Prod** intégrée au reste du projet

# Architecture UI

## Vue générale

L’interface graphique repose sur une architecture **MVC par écran**.

Exemple avec la vue mensuelle :

* `PublicationMonthModel`
* `PublicationMonthView`
* `PublicationMonthController`

## Rôle des composants

### Model

Le `Model` contient l’état nécessaire à l’affichage.

Exemples :

* année courante
* mois courant
* liste des publications affichées

Le modèle ne contient pas de logique JavaFX.

### View

La `View` construit et affiche l’interface JavaFX.

Responsabilités :

* afficher le calendrier
* afficher les publications
* gérer les composants visuels
* capter les événements utilisateur
* déléguer les actions

La vue ne contient pas la logique métier.

### Controller

Le `Controller` orchestre la vue.

Responsabilités :

* charger les données depuis le repository
* mettre à jour le modèle
* rafraîchir la vue
* gérer les actions propres à la vue courante

Exemples pour la vue mensuelle :

* `init()`
* `nextMonth()`
* `previousMonth()`

---

# PublicationActions

## Rôle

`PublicationActions` centralise les actions utilisateur transversales à plusieurs vues.

Exemples :

* voir une publication
* éditer une publication
* supprimer une publication
* créer une publication
* changer de vue

Cette interface permet de découpler :

* la logique spécifique d’une vue
* les actions fonctionnelles globales de l’application

## Principe de délégation

Le contrôleur de vue **n’implémente pas** directement `PublicationActions`.

À la place :

* il reçoit une implémentation de `PublicationActions`
* il la transmet à la vue
* la vue invoque cette interface selon les interactions utilisateur

Ce choix améliore :

* la modularité
* la testabilité
* la séparation des responsabilités

## Implémentations prévues

### `PublicationActionsDemo`

Implémentation légère pour tests rapides.

Comportement :

* affiche simplement une boîte de dialogue pour chaque action

Usage :

* prototypage UI
* démonstration
* validation rapide des interactions

### `PublicationActionsProd`

Implémentation réelle branchée sur le reste du projet.

Comportement attendu :

* ouverture de dialogues
* navigation réelle entre vues
* actions effectives sur les publications

# Exemple de flux MVC + Actions

## Navigation dans le mois

1. L’utilisateur clique sur **Mois suivant**
2. La vue appelle le contrôleur
3. Le contrôleur met à jour le modèle
4. Le contrôleur recharge les publications
5. La vue est rafraîchie

## Action sur une publication

1. L’utilisateur fait un clic droit sur une publication
2. La vue affiche un menu contextuel
3. La vue appelle `PublicationActions`
4. L’implémentation `Demo` ou `Prod` exécute l’action

## Ajout d’une publication

1. L’utilisateur clique sur `+` dans un jour ou sur **Nouvelle publication...**
2. La vue appelle `actions.createPublication(date)`
3. L’implémentation active décide du comportement
